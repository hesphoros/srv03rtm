## Windows Server 2003 (NT 5.2.3790.0) 构建指南

*版本 10a，上次更新时间：2020/11/29*

本构建指南已在 XP SP3 x86、Win7 SP1 x86/x64 和 Win10 x64 下测试通过，在其他操作系统下结果可能有所不同。

## 构建准备

---

- 建议在解压/构建之前禁用所有杀毒软件，因为这两个操作都会生成大量新文件（杀毒软件可能会扫描每个文件，从而显著降低解压/构建速度）。对于其他监控文件的工具，例如 voidtools 的 Everything，也应如此。

- **确保构建计算机的日期为当前日期** - 无需再将日期设置为 2003 年或其他任何日期。

- 将源代码树解压到驱动器根目录下的名为 `srv03rtm` 的文件夹中（**重要，因为预编译的 DirectUI 文件只能在此路径下正确链接**），驱动器盘符似乎无关紧要（但不要使用 C:\ 盘，因为它有一些额外的安全措施），请使用 `D:\srv03rtm\` 作为路径以匹配 RTM 二进制文件。

- 取消解压目录（包括子文件夹和文件）的只读属性（请注意，取消只读属性并关闭/重新打开文件夹属性后，您可能会看到只读属性再次被设置，这没关系，只要您取消一次只读属性，构建过程应该就能顺利进行）。

- 将此 ZIP 文件中的文件复制到源代码树中，必要时覆盖现有文件。

- **如果使用 64 位主机操作系统进行构建：** 将 ZIP 文件中 `_x64` 文件夹的内容复制到源代码树中，如果提示覆盖，请覆盖现有文件。

**如果您的操作系统不使用用户帐户控制 (UAC)（XP/2003）：**

- 为 `%windir%\system32\cmd.exe /k D:\srv03rtm\tools\razzle.cmd free offline` 创建桌面快捷方式（详见下文说明），并将“起始位置”更改为 `D:\srv03rtm`

- **如果您使用的是 64 位主机操作系统**，请在快捷方式中使用 `razzle64.cmd` 而不是 `razzle.cmd`

- 使用您创建的快捷方式打开 Razzle 窗口。

**如果您的操作系统使用用户帐户控制 (UAC)（Vista 及更高版本）：**

- 以管理员身份运行命令提示符（通常可以通过在开始菜单中输入 `cmd`，右键单击“命令提示符”->“以管理员身份运行”来完成）

- 在命令提示符中，通过输入驱动器号切换到您解压源代码的驱动器，例如： `E:`

- 切换到源文件夹：`cd srv03rtm`

- 启动 Razzle：`tools\razzle.cmd free offline`（**如果使用 64 位主机操作系统，**请改用 `tools\razzle64.cmd free offline`）

首次在该源代码副本中运行 Razzle 时，它​​需要初始化一些内容，请稍等片刻。过一会儿，会弹出一个记事本窗口——请务必关闭此窗口，以便初始化继续进行。

**重要提示：** Razzle 初始化完成后，运行 `tools\prebuild.cmd` 以完成构建环境的准备工作（只需在该目录树中首次初始化 Razzle 后运行一次）。

## 构建

---

**重要提示：** 目前，当使用多个线程（超过 4 个）进行构建时，构建过程似乎存在问题。如果您的构建机器拥有的线程数超过 4 个，建议通过在构建命令中添加 `-M 4` 开关将其限制为最多 4 个线程（例如，`build /cZP -M 4` 或 `bcz -M 4`）。

### 全新构建

对所有组件执行全新重建（**建议首次构建时使用！**）：

- `build /cZP`（`bcz` 也对应此命令）

### “脏”构建

仅构建自上次全新构建以来已更改的组件：

- `build /ZP`（`bz` 也对应此命令）

### 构建后

- 下载 [win2003_x86-missing-binaries.7z](https://gofile.io/d/SvWudI) 包，其中包含 x86fre 和 x86chk 构建所需的缺失二进制文件。

- 从该 7z 文件中，将您正在构建的构建类型的二进制文件夹的内容提取到您的构建树二进制文件夹（例如 `D:\binaries.x86fre`，该文件夹应该在构建过程中创建）中。该 7z 文件中应该包含所有 SKU 的文件（使用来自 Windows Server 2003 企业版的 pidgen.dll，因此您的构建应该能够接受企业版产品密钥）。

- **提取过程中，如果询问是否覆盖文件夹，请选择“是”；但如果询问是否覆盖文件（例如 DUser.pdb/dll），请务必选择“否”！**

- 添加缺失的文件后，您应该会看到诸如 `binaries.x86{fre/chk}\_pop3_00.htm`、`binaries.x86{fre/chk}\ql10wnt.sys` 等文件。

- 在 Razzle 窗口中运行 `tools\postbuild.cmd`（如果您只想处理特定 SKU，请使用 `-sku:{sku}`）。 （不要加括号！）如果您忽略此说明，并且没有为每个 SKU 使用 missing.7z / missing.cmd，则可能会出现 `filechk` 错误。

假设您使用了上述 `win2003_x86-missing-binaries.7z` 文件并正确遵循了指南，那么构建后应该会顺利完成，并且不会生成 `binaries.x86fre\build_logs\postbuild.err` 文件！

否则，请查看 `postbuild.err` 文件——其中的大多数消息都无关紧要，但如果您看到与您要使用的版本相关的 `filechk` 错误，则可能需要重新运行 `missing.cmd`，或者再次提取 `2k3-missing.7z`。

如果 `postbuild.err` 文件中包含类似 `(crypto.cmd) ERROR` 或 `(ntsign.cmd) ERROR` 的消息，请尝试重新导入 `tools\driver.pfx` 密钥文件（双击该文件，然后在提示符下单击“下一步”）。
